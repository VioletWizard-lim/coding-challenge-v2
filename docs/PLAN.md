# coding-challenge-v2 개발 계획

## 1. 왜 다시 만드는가

- **연구대회 방향**: 2026년 정보 교과 수상작들은 "AI가 학생에게 무엇을 말하는가"(힌트, 되묻기, 피드백)에 집중했다. 코드가 **실제로 어떻게 쓰였는지**(어디서 멈추고, 무엇을 지우고, 어디서 붙여넣었는지)를 보는 작품은 없었다. v1의 작성 과정 기록·재생 기능이 바로 그 빈자리다.
- **문제의식**: AI 시대에는 완성된 코드만 보고 학생이 직접 짰는지 알 수 없다. 평가와 성찰의 대상을 결과에서 과정으로 옮겨야 한다.
- **기술적 이유**: 기록·실행·재생이 이미 전부 브라우저 JS인데 Streamlit iframe에 감싸여 있다(편집기 높이 버그 등). 업적 알림 같은 실시간 반응, 동시접속 성능, 보안(평문 비밀번호·서명 없는 쿠키)을 함께 해결하려면 구조를 바꾸는 편이 낫다.

## 1-1. 심사 기준 (제20회 2026 요강 기준, 2027년 요강이 나오면 다시 확인)

| 영역 | 세부 항목 | 배점 | 이 프로젝트에서 준비할 것 |
|---|---|---|---|
| 연구 목적 (30) | **독창성**: 학생 역량을 높이는 주제인가, **기존 입상작·시판 SW와 차별화**되었는가 | 20 | 기존 입상작(코딩룸, 힌트 AI, 생각 먼저)·시판 SW(구름EDU, 코드잇 등)와 비교표. "AI가 무엇을 말하는가"가 아니라 "코드가 어떻게 쓰였는가"를 다룬다는 차별점 |
| | **타당성**: SW에 맞는 내용인가, 체계적 구성인가, 교육과정과 연계되는가 | 10 | 정보 교과 성취기준([12정03-xx])과 문제·단원 대응표 |
| 구현 기술 (20) | **안정성**: 오류 없이 구동되는가, **반응 속도**가 적절한가 | 10 | 잠들지 않기, 동시접속 부하 테스트 수치, 오류 로그 |
| | **우수성**: 학습동기 유발 기능, 교사-학생-콘텐츠 간 효율적 인터페이스 | 10 | 업적 시스템, 학생 재생·성찰, 교사 대시보드 |
| 수업 활용 (20) | **체계성**: 연구 목적·방법에 따라 수업 적용과 연구를 했는가, 개발과 적용 과정을 구체적으로 제시했는가 | 10 | 개발 일지(PR 기록), 차시별 수업 적용 기록, 사전·사후 검사 |
| | **효율성**: 수업 절차에 따른 자료 제시·전략 구현, 교실 수업에 맞는 인터페이스 | 10 | 수업 모형(작성→재생→분석→성찰)과 화면 흐름을 1:1로 대응 |
| 일반화·시사성 (30) | **일반화 가능성**: 다른 학교·교사가 적용 가능한가, 지속적으로 발전 가능한가 | 20 | 타교 교사 실사용, 타 교과(글쓰기 모드) 시범 적용, CSV 일괄 등록·교사 안내서, 무설치 웹 |
| | **시사성**: 구체적 시사점 도출, 결론·제언이 **기존 입상작·시판 SW와 차별화**되는가 | 10 | AI 시대 과정 중심 평가에 대한 제언 |

- 동점 시 일반화·시사성 → 연구 목적 → 수업 활용 → 구현 기술 순으로 우선
- "기존 입상작과 차별화"가 독창성(20)과 시사성(10) 두 곳에 들어 있음 → 보고서에 기존 입상작 비교를 반드시 넣는다
- 심사 절차: **사전심사**(정상 가동 여부 확인, 표절·저작권·연구윤리, 감점) → **서류심사**(SW + 보고서, 1등급 후보 선정 및 입상·등외 후보 결정) → **발표심사**(1등급 후보만, 서류 60% + 발표 40%로 최종 등급)
- **2·3등급은 사실상 서류심사에서 결정된다.** 심사위원이 혼자 접속해 SW를 써 보는 순간이 전부 → 언제 접속해도 바로 뜨고(잠들지 않기), 처음 보는 사람도 바로 핵심을 볼 수 있어야 함(`/try` 체험 페이지, 데이터가 채워진 심사용 계정, 접속 안내문)
- 사전심사 첫 항목이 "정상 가동 여부 확인" → 출품 기간 내내 상태 확인(Cron)과 오류 알림 유지
- 서류심사 후 대리·표절작 선별을 위해 **기술시연심사**를 할 수 있음 → 개발 과정 기록(PR, 개발 일지)을 남기고 직접 시연·설명할 수 있게 준비
- 감점: 분량 초과, 블라인드 미처리, 컬러 인쇄본 제출, 지정 글꼴 미준수 (항목당 1점, 최대 4점)
- **생성형 AI는 서비스 약관(연령 제한 등)을 지켜야 하며 위반 시 등외** → 학생용 AI는 미성년자 사용이 허용된 Claude API 사용
- 표절: 6어절 이상 일치, 카피킬러 20% 이상, 또는 핵심 아이디어·구성이 타인 저작물과 같으면 표절 → 2026 수상작(생각 먼저, 힌트 AI 등)과 핵심 아이디어가 겹치지 않게
- 보고서는 **흑백 인쇄** → 화면 캡처가 흑백에서도 구분되게(붙여넣기·창 이탈 표시는 색 외에 무늬·아이콘·글자로도 구분)
- 바탕체, 지정 글자 크기·여백, 블라인드 처리(위반 시 항목당 1점 감점)
- 개발 기능보다 "일반화"와 "연구 목적"이 배점의 60%: 타 교과 적용 실적, 타교 확산, 교사 1명이 바로 쓸 수 있는 운영 편의성이 중요

## 2. 수업 모형 (보고서용 이름은 추후 확정)

**작성 → 재생 → 분석 → 성찰**

1. 작성: 학생이 기록 편집기에서 코드를 쓰고 실행한다.
2. 재생: 제출 후 자기 작성 과정을 타임라인으로 다시 본다.
3. 분석: AI가 결과 코드가 아니라 과정 로그를 읽고 "어디서 막혔고 어떻게 돌파했는지" 서술한다.
4. 성찰: 학생이 재생과 AI 분석을 보고 회고를 쓴다. 업적이 좋은 과정 습관을 인정한다.

## 3. 단계별 일정

### 1단계 (11~12월): 뼈대와 학생 화면
- [ ] Next.js 프로젝트 생성, Supabase 연결, `.env.example`
- [ ] 잠들지 않게: `/api/health` + Vercel Cron 하루 1회 (Supabase 무료 프로젝트 7일 비활성 일시정지 방지), Pyodide 미리 불러오기
- [ ] 로그인: 기존 v1 학번·비밀번호 그대로 사용 (서명 쿠키 + bcrypt, `password_hash` 컬럼 추가 마이그레이션). 구글 로그인은 쓰지 않음(학교 계정 종료 예정, 타 학교 확산 고려)
- [ ] 교사가 학생 비밀번호 초기화 (교사 화면에서 바로 재설정)
- [ ] CSV로 학생 일괄 등록 (학번, 이름, 학년, 반, 과목, 초기 비밀번호 / 미리보기 후 등록, 중복 학번은 건너뛰고 알려 줌, 양식 파일 내려받기 제공)
- [ ] 기록 편집기 (CodeMirror 6, v1과 같은 edit_log 형식, localStorage 이어쓰기)
- [ ] Pyodide 실행 + 실행 기록 `[ms, "r:ok"|"r:오류이름"]`
- [ ] 학생 화면: 과목·문제 선택, 코드 설명, 제출, 내 제출 현황(점수·피드백·오답 이유)
- [ ] 문제 목록 이전 (v1 `problem_data.py`)
- [ ] 로그인 없이 써볼 수 있는 체험 페이지 `/try` (심사위원용 시연, 저장 안 함)

### 2단계 (12월~1월): 재생과 업적

- [ ] 학생이 자기 제출을 재생하는 화면
- [ ] 성찰 작성 (재생 후 "어디서 막혔고 어떻게 해결했나")
- [ ] 업적 시스템 (4절)

### 3단계 (1~2월): 교사 화면과 AI
- [ ] 채점 관리 (기능 40 / 코드 설명 40 / 도전 20, 피드백, 오답 처리, 삭제)
- [ ] 학생별 코드 확인 + 재생, 반별 현황, 작성 통계, CSV 내보내기(익명 ID 옵션)
- [ ] Claude API 자동 채점 보조: 지금은 화면을 캡처해 Gemini에 넘기는 수작업 → 코드 + 과정 로그 요약을 서버에서 Claude API로 보내고, 교사가 확인 후 확정
- [ ] AI 과정 분석 (Claude API, 학생에게 보여 줄 과정 서술)
- [ ] AI 질문 도우미 (지금 쓰는 Gemini Gems 대체)
  - 교사가 과목·단원별로 지침을 설정 (예: "정답 코드는 주지 말고 질문으로 이끌어라"), 기본값은 정답 코드 금지
  - 학생이 질문하면 지금 편집기의 코드와 문제를 함께 AI에 보냄 (이름·학번은 보내지 않음)
  - 질문 시점을 작성 기록에 표시 `[ms, "q"]` → 재생 타임라인에서 "여기서 AI에게 물었다"가 보이게
  - 대화 내용은 별도 테이블(`ai_chats`)에 저장, 교사와 본인만 열람
  - 학생별 하루 질문 횟수 제한 (API 비용 관리), 교사가 수업 중 켜고 끄기
  - 업적 연결 예: "질문 후 스스로 해결"
- [ ] 교사 계정 추가, 반별 업적 현황
