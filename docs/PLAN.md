# coding-challenge-v2 개발 계획

## 1. 왜 다시 만드는가

- **연구대회 방향**: 2026년 정보 교과 수상작들은 "AI가 학생에게 무엇을 말하는가"(힌트, 되묻기, 피드백)에 집중했다. 코드가 **실제로 어떻게 쓰였는지**(어디서 멈추고, 무엇을 지우고, 어디서 붙여넣었는지)를 보는 작품은 없었다. v1의 작성 과정 기록·재생 기능이 바로 그 빈자리다.
- **문제의식**: AI 시대에는 완성된 코드만 보고 학생이 직접 짰는지 알 수 없다. 평가와 성찰의 대상을 결과에서 과정으로 옮겨야 한다.
- **기술적 이유**: 기록·실행·재생이 이미 전부 브라우저 JS인데 Streamlit iframe에 감싸여 있다(편집기 높이 버그 등). 동시접속 성능, 잠자기 문제, 보안(평문 비밀번호·서명 없는 쿠키)을 함께 해결하려면 구조를 바꾸는 편이 낫다.

## 1-1. 기존 입상작과의 차별화 (가장 중요)

심사 기준의 독창성(20)과 시사성(10)이 모두 "기존 입상작·시판 SW와 차별화"를 묻는다. 표절 기준에도 "핵심 아이디어·구성이 같으면 표절"이 있다.

**AI가 무엇을 근거로 돕는가, 무엇을 기록하는가로 구분한다.**

| 작품 | AI가 돕는 근거 | 기록하는 것 |
|---|---|---|
| 생각 먼저 (2026) | 학생이 쓴 설계·글을 되묻기 (코딩 전) | 질문에 대한 학생 답변(결정 로그) |
| 답 대신 힌트를 주는 AI 파이썬 학습 프로그램 (2026) | **현재 코드**와 막힘 정보로 단계적 힌트 | 통과·시도 횟수·힌트 사용량 |
| 스스로 생각하고 실행하며 배우는 코딩룸 (2025 1등급) | 결과 코드 평가·피드백 | 결과물 |
| **이 프로젝트** | **학생 자신의 작성 과정**(마지막 성공 상태, 그 뒤 바뀐 부분, 반복된 오류, 막혔던 개념) | **키 입력 단위의 작성 과정 전체 + 도움 요청 전후 행동** |

AI 기능 세 가지가 모두 과정 기록을 근거로 한다:
- 작성 중: **과정 기반 도우미** — "5분 전엔 실행이 성공했어. 그 뒤 바뀐 줄을 비교해 볼래?"
- 제출 후: **되돌아보기** — 재생 타임라인의 특정 지점을 짚어 질문
- 연습: **내 막힘에서 만든 연습 문제** — 과정 기록에서 막혔던 개념으로 문제 생성

**만들지 않는 것** (기존 입상작과 겹치므로):
- 힌트 단계·힌트 쿨다운·힌트 사용 감점 구조
- 점수·레벨·칭호·보석·화폐·랭킹 (업적은 순수 업적으로만)
- 미션 해금 같은 진도 게임 구조
- AI가 결과 코드만 보고 채점·피드백하는 것을 핵심 기능으로 내세우기 (교사 채점 보조는 교사용 편의 기능으로만)

**학생 화면의 중심은 재생 타임라인과 나의 학습 여정이다.**

## 1-2. 심사 기준 (제20회 2026 요강 기준, 2027년 요강이 나오면 다시 확인)

| 영역 | 세부 항목 | 배점 | 이 프로젝트에서 준비할 것 |
|---|---|---|---|
| 연구 목적 (30) | **독창성**: 학생 역량을 높이는 주제인가, **기존 입상작·시판 SW와 차별화**되었는가 | 20 | 1-1절 비교표. 시판 SW(구름EDU, 코드잇 등)도 비교 |
| | **타당성**: SW에 맞는 내용인가, 체계적 구성인가, 교육과정과 연계되는가 | 10 | 정보 교과 성취기준([12정03-xx])과 문제·단원 대응표 |
| 구현 기술 (20) | **안정성**: 오류 없이 구동되는가, **반응 속도**가 적절한가 | 10 | 잠들지 않기, 동시접속 부하 테스트 수치, 오류 로그 |

| 수업 활용 (20) | **체계성**: 연구 목적·방법에 따라 수업 적용과 연구를 했는가, 개발과 적용 과정을 구체적으로 제시했는가 | 10 | 개발 일지(PR 기록), 차시별 수업 적용 기록, 사전·사후 검사 |
| | **효율성**: 수업 절차에 따른 자료 제시·전략 구현, 교실 수업에 맞는 인터페이스 | 10 | 수업 모형(작성→재생→되돌아보기→성찰)과 화면 흐름을 1:1로 대응 |
| 일반화·시사성 (30) | **일반화 가능성**: 다른 학교·교사가 적용 가능한가, 지속적으로 발전 가능한가 | 20 | 타교 교사 실사용, 타 교과(글쓰기 모드) 시범 적용, CSV 일괄 등록·교사 안내서, 무설치 웹 |
| | **시사성**: 구체적 시사점 도출, 결론·제언이 **기존 입상작·시판 SW와 차별화**되는가 | 10 | AI 시대 과정 중심 평가에 대한 제언 |

- 동점 시 일반화·시사성 → 연구 목적 → 수업 활용 → 구현 기술 순으로 우선
- 심사 절차: **사전심사**(정상 가동 여부 확인, 표절·저작권·연구윤리, 감점) → **서류심사**(SW + 보고서, 1등급 후보 선정 및 입상·등외 후보 결정) → **발표심사**(1등급 후보만, 서류 60% + 발표 40%로 최종 등급)
- **2·3등급은 사실상 서류심사에서 결정된다.** 심사위원이 혼자 접속해 SW를 써 보는 순간이 전부 → 언제 접속해도 바로 뜨고(잠들지 않기), 처음 보는 사람도 바로 핵심을 볼 수 있어야 함(`/try` 체험 페이지, 데이터가 채워진 심사용 계정, 접속 안내문)
- 사전심사 첫 항목이 "정상 가동 여부 확인" → 출품 기간 내내 상태 확인(Cron)과 오류 알림 유지
- 서류심사 후 대리·표절작 선별을 위해 **기술시연심사**를 할 수 있음 → 개발 과정 기록(PR, 개발 일지)을 남기고 직접 시연·설명할 수 있게 준비
- 감점: 분량 초과, 블라인드 미처리, 컬러 인쇄본 제출, 지정 글꼴 미준수 (항목당 1점, 최대 4점)
- **생성형 AI는 서비스 약관(연령 제한 등)을 지켜야 하며 위반 시 등외** → 학생용 AI는 미성년자 사용이 허용된 Claude API 사용
- 표절: 6어절 이상 일치, 카피킬러 20% 이상, 또는 핵심 아이디어·구성이 타인 저작물과 같으면 표절
- 보고서는 **흑백 인쇄** → 화면 캡처가 흑백에서도 구분되게(붙여넣기·창 이탈 표시는 색 외에 무늬·아이콘·글자로도 구분)
- 개발 기능보다 "일반화"와 "연구 목적"이 배점의 60%: 타 교과 적용 실적, 타교 확산, 교사 1명이 바로 쓸 수 있는 운영 편의성이 중요

## 2. 수업 모형 (보고서용 이름은 추후 확정)

**작성 → 재생 → 되돌아보기 → 성찰**

1. 작성: 학생이 기록 편집기에서 코드(또는 글)를 쓰고 실행한다. 막히면 과정 기반 도우미에게 묻는다. 도움 요청도 기록된다.
2. 재생: 제출 후 자기 작성 과정을 타임라인으로 다시 본다. 멈춘 구간, 오류, 붙여넣기, 고쳐 쓴 흔적, 도움 요청 지점이 표시된다.
3. 되돌아보기: AI가 결과 코드가 아니라 과정 기록을 읽고, 타임라인의 특정 지점을 짚어 질문한다. 예: "3분 20초에 7분 동안 멈췄다가 반복문을 새로 썼네. 그때 무엇이 막혔어?" AI는 정답이나 고친 코드를 주지 않는다.
4. 성찰: 학생이 AI 질문에 답하며 회고를 쓴다. 막혔던 개념은 연습 모드로 이어지고, 학습 여정 화면에서 성장을 확인한다.

  - 새 표 `schools`(학교 코드·이름) + `users.school`(새 칸, nullable — 비어 있으면 우리 학교). v1은 이 칸을 모르므로 영향 없음
  - **아이디에 학교 코드**: 학교마다 학번이 겹치므로 새 학교 계정은 `학교코드-학번` 같은 규칙. 우리 학교 기존 아이디는 그대로(학교 칸으로 구분)
  - **모든 조회에 학교 조건**: 교사는 자기 학교 학생·제출·AI 대화·학생이 만든 문제만, 학생의 "같은 반"도 같은 학교 안에서만. 문제·채점 기준·연습 모드·AI 기능 설정도 학교마다
  - **관리자 두 단계**: 사이트 관리자(학교 추가, 학교 관리자 지정) / 학교 관리자(그 학교 교사 계정). 지금의 `role=admin`은 사이트 관리자로
  - **교사 ↔ 담당 반 연결**: AI 사용량·처음 화면을 교사별로 (지금은 학교 전체)
  - **AI 비용·한도**: 학교별 사용량 보기, 필요하면 학교별 하루 한도
  - 개인정보 안내 페이지에 "학교마다 정보가 나뉘어 저장되고, 다른 학교 선생님은 볼 수 없다"를 더하고, 학교마다 동의서
  - 지금 만드는 기능도 학교가 늘어날 것을 생각해 "학교 전체"를 전제로 한 조회(예: 교사 화면의 모든 학생)는 한 곳(`src/lib/teacher.ts` 등)에 모아 두면 나중에 학교 조건을 넣기 쉽다
- (참고) 학교마다 따로 설치하는 방식은 쓰지 않는다: 업데이트·관리 부담이 학교 수만큼 늘어남
- 교사 PC에 설치된 교사 본인의 AI 구독(Claude Code 등)으로 채점 초안을 만드는 방식 (이음오피스처럼). API 비용을 줄일 수 있지만 회사 약관이 자주 바뀌어 우선은 API로 한다.

## 4. 업적

**순수 업적**: 조건을 달성하면 알림이 뜨고 업적 목록에 모인다. 점수·레벨·화폐·보석·랭킹과 연결하지 않는다. 다른 학생과 비교하는 화면은 만들지 않는다. 업적을 누르면 달성한 순간의 재생 지점으로 이동한다.
