# 동시접속 부하 테스트 (보고서용)

한 반(30명)이 수업에서 **동시에 로그인하고 동시에 제출하는 순간**을 흉내 내어, 실제 수업 사이트가 얼마나 빨리 응답하는지 잰다.
도구: `scripts/load-test.mjs` (Playwright, 실제 브라우저 30개).

## 무엇을 재는가

| 값 | 뜻 |
|---|---|
| 로그인 응답 (`loginMs`) | 30명이 같은 순간 "로그인"을 눌렀을 때, 서버가 아이디·비밀번호를 확인하고 학생 첫 화면을 보내기 시작할 때까지 |
| 제출 응답 (`submitMs`) | 30명이 같은 순간 "제출하기"를 눌렀을 때, 서버가 코드·설명·작성 기록(edit_log)을 DB에 저장하고 응답을 보내기 시작할 때까지 |
| 제출 뒤 학생 화면 (`studentPageAfterSubmitMs`) | 제출 직후 학생 화면을 새로 열 때, 서버가 방금 쓴 제출까지 읽어(학습 여정·업적·첫 화면) 그리기 시작할 때까지 |
| 성공 수·오류 | 로그인 → 코드 작성 → 제출 완료까지 끝까지 간 사람 수, 실패한 사람과 이유 |

- 시간은 브라우저가 잰 **서버 응답 시간**(요청을 보낸 뒤 응답 첫 바이트가 올 때까지)이다. 테스트하는 컴퓨터가 브라우저 30개를 돌리느라
  느려지는 것(글자 입력 등)은 넣지 않는다.
- 결과는 평균, 중앙값(p50), 95% 값(p95: 30명 중 가장 느린 1~2명을 뺀 값), 최댓값으로 적는다.

## 절차

1. **테스트 계정 30개 등록**: 교사 화면 🏫 학생 관리 → CSV 등록으로 `부하테스트_계정30.csv`를 올린다.
   아이디 `loadtest01`~`loadtest30`, 이름 "부하테스트01"~, 가상 반 9학년 99반, 과목 프로그래밍. 비밀번호가 들어 있으므로 이 파일은 저장소에 넣지 않는다.
2. **공개된 프로그래밍 문제가 하나 이상** 있어야 한다(테스트 계정이 그 문제에 제출).
3. **수업이 없는 시간**에 실행한다(실제 수업 DB를 함께 쓰므로).
   ```bash
   node scripts/load-test.mjs --base https://line-by-line-class.vercel.app --accounts 부하테스트_계정30.csv --users 30 --out result.json
   ```
4. **정리**: 🛠 관리자 → 🧑‍🎓 학생 삭제 요청 탭 → "🧪 부하 테스트 계정 정리"에서 "부하 테스트 계정 삭제"를 적고 지운다.
   `loadtest`로 시작하는 학생 계정과 그 계정의 모든 기록(제출·작성 기록 등)이 지워진다. 다른 학생은 그대로다.
